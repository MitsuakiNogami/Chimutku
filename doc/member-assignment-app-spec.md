# メンバー割り振りアプリ 仕様まとめ

## 目的

複数人の参加者を、ボーリング、ダーツ、その他イベントの決められたフォーマットに合わせてランダムに割り振るアプリケーション。

競技ごとの専用ロジックに閉じず、基本的には以下の考え方で設計する。

- 参加者を入力する
- 抽選結果ごとに集計用タグを登録する
- フォーマットを選ぶ
- フォーマット内の枠に参加者を割り振る
- 割り振り後に勝敗を登録する
- 結果を確認、コピー、保存、再利用する
- 保存済み履歴を横断して分析する

## 基本モデル

```ts
type Participant = {
  id: string;
  name: string;
  active: boolean;
};

type Slot = {
  id: string;
  label: string;
  capacity: number;
};

type Format = {
  id: string;
  category: "bowling" | "darts" | "custom";
  name: string;
  slots: Slot[];
};

type Assignment = {
  slotId: string;
  slotLabel: string;
  capacity: number;
  participants: Participant[];
  outcome?: "win" | "loss" | "";
};

type AssignmentResult = {
  assignments: Assignment[];
  resultTags: string[];
};
```

## テンプレートカテゴリ

テンプレートはタブでカテゴリ分けする。

- ボーリング
- ダーツ
- カスタム

各タブを選択すると、そのカテゴリに属するテンプレートのみを表示する。

## ボーリング仕様

ボーリングでは、レーン数と各レーンごとの人数を変更できる。

例:

```txt
レーン数: 3

1レーン人数: 2
2レーン人数: 4
3レーン人数: 3
```

この場合、合計9名までを各レーンに割り振る。

参加者が定員を超える場合は、余った参加者を `待機` として表示する。

## ダーツ通常テンプレート

ダーツでは以下の通常テンプレートを持つ。

- ダーツリーグ戦 13試合
- プレイオフ 13試合
- 関東大会 5試合
- ダーツ 01 ダブルス
- クリケット トリオス

## ダーツリーグ戦フォーマット

ダーツリーグ戦では、第1戦から第13戦までの試合形式が固定されている。

人数ルール:

- シングル: 1名
- ダブルス: 2名
- トリオス: 3名
- ガロン: 4名

試合構成:

```txt
第1戦  701 トリオス
第2戦  クリケット トリオス
第3戦  501 ダブルス
第4戦  501F ダブルス
第5戦  701 シングル
第6戦  クリケット シングル
第7戦  901 トリオス
第8戦  クリケット トリオス
第9戦  クリケット ダブルス
第10戦 501F ダブルス
第11戦 501 シングル
第12戦 クリケット シングル
第13戦 1101 ガロン
```

合計は延べ27出場枠。

## プレイオフフォーマット

プレイオフでは、第1戦から第13戦までの試合形式が固定されている。

試合構成:

```txt
第1戦 701 トリオス
第2戦 クリケット トリオス
第3戦 501 ダブルス
第4戦 501F ダブルス
第5戦 701 シングル
第6戦 クリケット シングル
第7戦 901 トリオス
第8戦 クリケット トリオス
第9戦 クリケット ダブルス
第10戦 501F ダブルス
第11戦 501セパ シングル
第12戦 クリケット シングル
第13戦 1101 ガロン
```

合計は延べ28出場枠。

プレイオフでは以下の制約を加味する。

- 参加者は4名以上必須
- 前半6ゲームで1人の最大出場ゲーム数は3ゲームまで
- 後半7ゲームで1人の最大出場ゲーム数は4ゲームまで
- 1人が参加できる最大ゲーム数は7ゲームまで
- シングルは1人最大2ゲームまで
- 自動抽選時と個別入れ替え時の両方で、シングル2ゲーム上限をチェックする
- 同じ試合内で同じ人を重複させない
- 制約上どうしても埋められない場合は `空き` として表示する

## 関東大会フォーマット

関東大会では、第1戦から第5戦までの試合形式が固定されている。

試合構成:

```txt
第1戦 901 トリオス
第2戦 クリケット トリオス
第3戦 501F ダブルス
第4戦 クリケット ダブルス
第5戦 1101 ガロン
```

合計は延べ14出場枠。

関東大会テンプレートも、ダーツリーグ戦と同じく複数出場型のフォーマットとして扱う。

関東大会では、参加者は4名以上必須とする。

## ダーツリーグ戦の制約

ダーツリーグ戦では以下の制約を加味する。

- 参加者は4名以上必須
- 1人が参加できる最大ゲーム数は7ゲームまで
- シングルは1人最大2ゲームまで
- 自動抽選時と個別入れ替え時の両方で、シングル2ゲーム上限をチェックする
- 同じ試合内で同じ人を重複させない
- 出場回数が少ない人を優先して割り振る
- 制約上どうしても埋められない場合は `空き` として表示する

## ダーツリーグ戦の前半・後半

ダーツリーグ戦では、試合を前半・後半に分ける。

- 第1戦から第6戦まで: 前半
- 第7戦から第13戦まで: 後半

メンバーごとに、前半・後半それぞれで優先設定を持てる。

優先設定:

- 指定なし
- 01優先
- クリケ優先

割り振り時には、ゲーム種別に応じて優先設定を重みとして加味する。

ゲーム種別の判定:

- クリケットを含む試合: クリケット
- それ以外: 01

## ダーツリーグ戦の個別編集

ダーツリーグ戦では、割り振り後に各枠を個別に変更できる。

各出場枠はプルダウンで表示され、以下が可能。

- 別メンバーに入れ替える
- 空きにする
- 空き枠にメンバーを入れる

手動変更時にも以下をチェックする。

- 同じ試合内で同じ人を重複させない
- 1人最大7ゲームを超えない
- シングル最大2ゲームを超えない

## カスタム仕様

カスタムでは以下を指定できる。

- 枠数
- 1枠あたりの人数

例:

```txt
枠数: 5
1枠あたりの人数: 4
```

この場合、5枠に4名ずつ割り振る。

## 割り振りロジック

通常フォーマットでは、以下の流れで割り振る。

1. 参加者を取得
2. Fisher-Yates方式でシャッフル
3. 各枠の定員に従って順番に割り振る
4. 入りきらない参加者は待機にする

ダーツリーグ戦では、参加者を複数試合に割り当てる。

1. 各参加者の総出場数を管理
2. 各参加者のシングル出場数を管理
3. 試合ごとに候補者を抽出
4. 上限を超えない候補者から選ぶ
5. 前半・後半の優先設定を重みとして加味する
6. 出場数が少ない人を優先する

## 履歴機能

抽選結果を履歴として保存できる。

保存する内容:

- 保存日時
- カテゴリ
- フォーマットID
- フォーマット名
- 参加者入力内容
- 抽選結果タグ
- カスタム設定
- ボーリング設定
- ダーツリーグ優先設定
- 割り振り結果
- 試合ごとの勝敗

履歴では以下ができる。

- 現在の結果を履歴保存
- 過去の履歴を閲覧
- 過去の結果を表示して再利用
- 保存済み履歴を読み込んだあと、勝敗やメンバー入れ替えを更新
- 保存済み履歴のタグを更新
- 履歴と設定をJSONファイルとして書き出し
- 別端末でJSONファイルを読み込み
- 履歴を個別削除
- 履歴を全削除

履歴は `localStorage` に保存する。

保存済み履歴を読み込んだあとに勝敗を登録・変更した場合は、その履歴データにも変更を反映する。

## データ移行

履歴はブラウザ内の `localStorage` に保存されるため、端末をまたいで自動同期はされない。

別スマホへ移すために、履歴パネルに以下の操作を用意する。

- 書き出し: 履歴、勝敗、タグ、参加者、フォーマット設定をJSONファイルとして保存する
- 読み込み: 別端末でJSONファイルを選択し、現在の履歴と設定を上書きして復元する

読み込み時は既存データを上書きするため、確認ダイアログを表示する。

## タグ機能

抽選結果ごとにタグを登録できる。

想定用途:

- 年間3シーズンのうち、どのシーズンの結果かを登録する
- 例: `2026春`, `Season1`, `前期`
- 後から分析タブで、同じタグの履歴をまとめて集計する

タグ仕様:

- タグはカンマ、スペース、読点区切りで複数登録できる
- 例: `2026春 Season1`
- スペースはタグの区切りとして扱うため、1つのタグ名にはスペースを入れない
- タグは抽選結果単位で `localStorage` に保存する
- シーズン中は同じタグを使う可能性が高いため、前回登録したタグを次回も初期表示する
- 抽選結果を履歴保存する際は、その時点の結果タグも履歴に保存する
- 保存済み履歴を読み込んだ場合は、履歴に保存された結果タグを復元する
- 保存済み履歴のタグは、履歴一覧から更新できる

タグ欄には、分析時に同じタグ単位で集約できる旨を表示する。

## 勝敗登録

割り振り後の各試合カードに、勝敗入力欄を表示する。

勝敗:

- 未入力
- 勝ち
- 負け

勝敗は試合単位で登録する。

保存済み履歴を読み込んだあとでも勝敗を登録・変更できる。

## 分析タブ

結果欄には `結果` と `分析` の表示切替タブを置く。

分析タブでは、保存済み履歴に含まれる結果タグと勝敗を加味して集計する。現在表示中の未保存結果に勝敗が入力されている場合は、その結果も集計対象に含める。

表示内容:

- タグ関係なく全試合での勝率
- タグ単位での勝率
- 組み合わせ単位での勝率
- 組み合わせ単位での勝率をタグ、またはタグの組み合わせで絞り込むフィルタ
- 最も勝率が高い組み合わせ

集計ルール:

- 勝敗が `未入力` の試合は集計対象外
- 全試合勝率は、勝敗入力済みの試合数を母数にする
- タグ別勝率は、該当タグが付いた履歴内の勝敗入力済み試合数を母数にする
- 組み合わせ別勝率は、同じ試合に割り振られたメンバー名の組み合わせを母数にする
- 組み合わせ別勝率のタグフィルタを選択した場合は、該当タグが付いた履歴のみを対象にする
- `2026 season1` のように複数タグが付いた履歴がある場合は、そのタグの組み合わせもフィルタ候補として表示する
- タグがない抽選結果は `タグなし` として集計する

## 個人別出場数サマリー

抽選後の結果欄では、個人ごとに何試合割り振られたかを確認できる。

表示内容:

- 個人名
- 合計出場数
- ダーツ複数試合フォーマットでは、シングル出場数
- ダーツ複数試合フォーマットでは、前半出場数
- ダーツ複数試合フォーマットでは、後半出場数
- 通常フォーマットでは、待機数

個別入れ替えを行った場合も、表示は再集計される。
コピー用テキストにも個人別出場数を含める。
